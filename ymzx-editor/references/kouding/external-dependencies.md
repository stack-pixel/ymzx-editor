# 扣叮关联资源

扣叮工程只保存逻辑及引用，不能代替UI、场景和素材的正常创建及保存。已有合适资源时直接核对和绑定；不为每个引用自动新建对象。

| 引用类别 | 核对内容 |
|---|---|
| UI | 真实UID、控件子类型、所属分组、初始显隐、命中区域和玩家范围 |
| 场景元件 | 实例ID、类、所在地图及层、变换、碰撞及事件要求 |
| 逻辑元件与信号 | 实例、信号定义、参数类型、接收方和归属工程 |
| 模板与模组 | 模板资源ID和运行实例ID分开；运行时创建不算编辑模式摆放 |
| 图片及其他素材 | 真实资源ID、可用类型、使用权限及目标地图依赖登记 |
| 预设与运动 | 所属对象、预设或轨道身份、当前参数；按实际需求配置 |

UI引用字段使用当前积木定义中的`inputName`和`custom_field_ui_id`结构，保留真实序列化值及子类型约束。显示名不能替代UID。字段格式及工具见[原生联动](native-editing.md)。

固定引用通过`resourceReferences`与原生编辑器交叉核对；变量和运行时生成对象追溯赋值来源，不能误判为缺少作者对象。查询目录、发现类型或方法名不等于相应资源已创建、可写或已保存。

## 联动顺序

1. 读取当前工程和资源基线，分别记录地图、层、资源类别、稳定ID、类型和采集时间。
2. 使用[UI](../ui/workflow.md)或[元件](../components/workflow.md)流程处理实际缺少的资源，取得正常创建的真实ID。
3. 绑定扣叮，导入后重新取得基线，再编译暂存。完整反射参数和非空UObject由工具检查，不猜测缺参调用。
4. 按各编辑器正常流程保存，确认UI、资源依赖、脚本和整图结果，再试玩并重开核验。

跨编辑器操作没有统一事务。`before-apply`只保护扣叮工程；资源复制、删除、重建改变ID时，需要修复受影响引用。超时先读取状态，避免重复创建。

UI事件和动作还需核对客户端/服务端语义及玩家参数。本地显示或点击通过不能证明多人同步。不要将内部模块方法名当作可直接调用的公开HTTP接口。
