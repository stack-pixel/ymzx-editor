# 共用连接与运行条件

四个分类共用本地执行环境，不依赖AI宿主Computer Use。AI读取文件并调用CLI；CLI访问原生接口，必要时调用随包Windows输入或标准文件对话框适配器，再读回结果。宿主现有工具使用规则仍适用。

| 分类 | 必要条件 | 不需要 |
|---|---|---|
| UI | Windows游戏主机、Node.js22+、原生编辑器服务；交互时PowerShell/Win32 | 扣叮页面、Lua监听器、图片创作服务 |
| 扣叮 | 同上，加指纹匹配的扣叮前端及本地桥接服务 | AI浏览器控制功能 |
| Lua | Windows、Node.js22+、本机DreamHelper1.4.7、当前工程监听器和原生编程面板 | 扣叮工程 |
| 元件 | Windows游戏主机、Node.js22+、原生编辑器服务；交互时PowerShell/Win32 | 扣叮页面、运行时Spawn脚本 |

原生服务地址为`127.0.0.1:30010`。先检查当前编辑器是否在线，查询当前world、根窗口及目标类型。不在线则报告连接缺失，不使用历史路径写入；本包不自动启动游戏或为未知版本开启服务。

沿用当前工作区与`YMZX_STATE_DIR`。没有状态目录时创建任务自己的目录；已连接电脑直接复用。命令中的技能目录、地图路径、PID均替换为当前真实值。可读取`.local/ymzx-skill-context.json`必要的工程上下文，不输出密钥或整个私有文件。

同一编辑器只允许一个控制方串行写入。已有监听器先检查身份/工程，不重复启动；端口冲突不结束未知进程。游戏重开、切地图或层后重新获取原生路径、目标和会话。扣叮与Lua各用自己的监听器和握手，不能互相替代。

只有远程HTTP能力的AI还需主机部署受控命令执行入口；本包没有统一MCP/HTTP网关。纯聊天上传SKILL.md不能操控游戏。可执行本机命令的AI直接使用完整技能目录；未逐一验证所有AI或游戏版本。

已有授权按当前用户任务范围执行，不反复询问普通编辑、保存和试玩；不自动转让到其他项目。编辑、上传、保存和对外发布分别记录。迁移只交付说明和自编工具，不带会话、令牌、日志、地图缓存、密码或官方资产。见[复用](reuse.md)与[验证](verification.md)。

## 首次使用检查

确认Node.js 22+、PowerShell及游戏PC编辑器可用。在技能目录运行对应分类的`help`查看现有入口；帮助不需要连接游戏。选择任务状态目录并设置`YMZX_STATE_DIR`，与技能安装目录分开存放。

UI或元件任务先使用`native-ui-inspect roots`、必要时使用`native-scene-snapshot`读取当前world和目标；扣叮先`status`再`info`；Lua先`status`核对已配置工程与握手。依赖缺失按相应分类安装说明处理，不自动修改未知版本游戏配置。

技能升级保留外部状态目录。分发只包含`SKILL.md`、`agents/`、`references/`和`scripts/`，排除运行目录、连接记录、日志、截图、地图缓存和官方依赖。安装与兼容信息见[扣叮接入](kouding/setup.md)、[Lua流程](lua/workflow.md)及[复用](reuse.md)。
