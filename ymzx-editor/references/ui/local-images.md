# 本地图片上传与替换原生 UI

本地图片文件→原生上传/审核/资源登记→真实图片ID→原生控件绑定→正常保存→脚本与试玩。手绘导出、设计软件制作和网上下载的图片均走相同链路；使用前核对素材授权和平台审核要求。能导入不等于自动获得素材使用权。

## 1. 准备图片

准备已经存在的本地图片，确认路径、格式、尺寸、透明背景需求及是否自带标题。保留原文件、文件摘要、用途和必要的素材来源/许可记录。网上下载的素材先保存为真实本地文件，再通过同一文件选择器上传。

随包静态文件选择适配器接受PNG、JPG、JPEG和BMP；透明图可用PNG。记录源文件尺寸、透明通道和摘要，尺寸及编码以当前平台要求为准。静态图片与GIF限制分开，不套用其他格式的大小上限。

选择实际存在且有使用权限的文件，保留来源记录。失败时根据最终上传结果和客户端错误定位，不仅凭文件名、缩略图或单次重试推定原因。

## 2. 正常上传

元梦原生界面编辑器→自定义→新增图片→Windows文件选择器选择实际文件→等待上传结果。正常流程会处理预审核、纹理编码、正式登记及资源上传。观察“成功N张/失败N张”和图库中的新条目，记录名称与结果；不要只凭缩略图判成功。

随包标准文件对话框适配器负责图片多选提交，不需要宿主Computer Use。先取得当前游戏PID并打开真实新增图片对话框；将1～10个实际本地图片绝对路径写入UTF-8 JSON数组，例如`["C:/assets/icon.png"]`，再调用：

```text
powershell -NoProfile -File scripts/common/game-file-dialog-native.ps1 -TargetProcessId ACTUAL_PID -Action inspect
powershell -NoProfile -File scripts/common/game-file-dialog-native.ps1 -TargetProcessId ACTUAL_PID -Action choose -FilesJson ABS_FILES_JSON
```

适配器检查游戏进程、唯一可见游戏所属`#32770`对话框及已观察的文件名/打开控件，设置文件名、读回一致后提交。图片扩展名限PNG/JPG/JPEG/BMP；结构不匹配会拒绝。它不负责点击新增图片，也不负责平台上传/审核。`uploadVerified:false`说明只提交了选文件，必须等待元梦成功/失败数量及真实资源登记。文件对话框不是主游戏窗口，不能套主窗坐标。

不要伪造 `_MOE.OnImagesPickedResult`、直接调用私有HTTP上传、虚构ugcId或跳过审核。用户已允许正常图片上传时不再重复索取许可。

## 3. 绑定和保存

选中**正确的原生控件UID**→编辑属性→底图/图片→自定义图库→选实际新图。这里的选图与“创建一个新图片控件”不同，不能误增控件。

图库选择可能保持窗口打开；正常返回属性、退出UI编辑器，再正常保存地图。作者数据中的素材引用为：

```text
#_*_#<真实ugcId>
```

只读解析保存文件，用`waitUIDocument`同时匹配目标`uid`、`name`及预期`assetName`，等待连续两次相同文件摘要；不能仅匹配旧名称或文字。正常选图/保存也用于登记地图的资源依赖；只在Lua写 `SetImage` 不证明依赖已打包。

可以用 `scripts/ui/custom-image-bindings.mjs` 从保存文档生成任务自己的JSON/Lua映射，见 [复用与交接](../reuse.md)。它要求显式列出控件UID，只提取已经绑定的真实自定义资源，不修改游戏缓存。资源ID全程字符串，不能转JS Number。

## 4. 运行时替换

需要运行时脚本时使用本技能 [Lua分类](../lua/workflow.md)：

```lua
UI:SetImage({buttonUID}, resourceIdString, true)
UI:SetImageColor({buttonUID}, "#FFFFFFFF")
```

检查原样式函数是否又设置内置底图或颜色，为自定义图建立映射分支；需要保留原交互时保持原UID和点击注册。若图片已含标题，则清空原生按钮文字并在周期Render里保持不叠字。下一批图可不烘焙标题，使用独立原生文本方便本地化和修改字号。

需要改变Lua后，按Lua分类检查、打包、真实元件导入、保存；仅图片作者数据改变且现有脚本不覆盖它时，不必无故重导脚本。

## 5. 实际验收与失败排查

按[接口与坐标验证](../verification.md)动态定位图标并进行实际点击，检查对应面板及行为数据；输入回执成功但没有预期变化时不通过。显示、透明边缘、颜色、长宽比和文字另用当前截图核对。保存原图/来源记录、名称与真实ID映射、作者数据读回、脚本构建标识、试玩截图与行为结果。

| 现象 | 接下来检查 |
|---|---|
| 有缩略图但上传失败 | 等最终结果，记录具体错误；缩略图只证明读取图片成功 |
| 无法保存到资源库 | 登记、编码、打包或后续上传的统合错误，不能仅凭文字断言文件大小或配额 |
| 作者界面选图成功，运行变回默认 | 启动样式、周期Render和显隐覆盖 |
| 图片偏粉/偏绿，或叠原生文字 | 旧染色、图片是否含标题、周期文字刷新 |
| 图标压扁/拉长、换设备出框 | 源图与最终内容比例、父级非等比缩放、viewport/安全区、锚点与DPI；见[适配检查](responsive.md) |
| 图库有资源但新地图不显示 | 是否在目标地图正常绑定并保存依赖，资源ID/使用权限是否正确 |
| 请求超时/客户端退出 | 先读现状、保存文件和当前进程；恢复后丢弃旧对象路径，逐步保存，不循环提交同一写入 |

## 发布上线

上传图片、保存地图和发布上线分别验证。用户明确要求发布时，通过元梦正常发布/审核流程检查图片在发布版本是否可用；不要由本地试玩推定已经上线。分别记录上传、绑定、保存、试玩和发布状态。
