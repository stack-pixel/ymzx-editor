# 跨设备布局、防出框与图片比例

新建或调整HUD、弹窗及图片后都读取此文。只在本机窗口显示正常，不代表完成跨设备适配。使用原生UI和用户选定的脚本分类；接口编辑、坐标点击与事件验收沿用[共用方案](../verification.md)。

## 目标设备与可用区域

依据项目要求记录设备、方向、最小窗口、输入方式及界面密度，不默认手机优先或固定横屏。设计画布只是制作单位，不是所有设备的固定分辨率。

设备安全边距、系统HUD和游戏操作区分别核对。预留项目实际使用的控制区域，不假定每张地图都有摇杆、跳跃键或同类HUD。无法从已核实接口读取安全区时，使用明确的项目配置并记录验证范围。

字号、命中范围与图片显示尺寸分别确定，空间不足时重排、分页或滚动，不无限缩小。pt、dp、物理像素和元梦UI单位不能未经校准互换。不可仅凭宽高比或性能等级识别设备类别；`GetDeviceLevel`不是手机/电脑判别接口。

HUD与跟随世界的文字分别诊断。移动设备目标需要真实触控验收；电脑窗口模拟只覆盖比例及部分布局。只报告实际完成的设备验证。

## 先区分四种尺寸

- 设计画布与地图作者坐标：只用于存储/制作，不等于设备实际可见区域。1920×1080换算2560×1440的固定比例不是自动适配。
- 当前游戏viewport：使用客户区实际可见宽高，不用显示器全分辨率，也不把标题栏计入。确认窗口、全屏模式和DPI。
- UI坐标：先读当前SDK及实际值；`UI:GetUISize()`声明返回UI系统分辨率，不应未经核对就当成物理屏幕或安全区域。必要时用已验证的屏幕/UI坐标转换，在目标控件或父容器坐标系内校准。
- 实际渲染矩形：包含父级变换、渲染缩放和偏移后的最终显示范围，用它判断出框、变形和命中。`GetSize`或保存文件矩形本身不证明最终显示范围。

## 布局约束

按界面设计选择边缘或中心锚点，例如边缘工具栏随对应边缘定位、居中弹窗随可用区域中心定位。把同一菜单/弹窗作为整体布局，保留内部相对关系；不要把每个子控件独立夹回屏幕边缘，导致叠在一起。

在同一坐标系中取得可见安全矩形后，可用统一contain缩放作为保底：

```text
safeW = viewportW - leftInset - rightInset
safeH = viewportH - topInset - bottomInset
s = min(safeW / designW, safeH / designH)
```

宽高使用同一个`s`，再按所选边缘/中心锚点定位。校验整体和每个可见子项都在安全矩形内，弹窗子项还须落在父容器内。安全边距、刘海区域、系统HUD和操作区需要按实际设备或产品约定取得；不能假定任意设备都有同样的安全区接口。仅检查屏幕边界不能排除与系统按钮重叠。

上述计算可以避免几何越界，但极窄/小窗口可能被缩得无法阅读或点击。此时折叠菜单、减少每行列数、分页/滚动或采用紧凑布局；不要为了通过边界检查无限缩小，也不要分别拉伸宽高。字体下限、点击目标下限和最小支持窗口由产品确定，另做可用性验收。竖屏需要单独布局时，不能由横屏contain成功推定竖屏可用。

布局在首次有效尺寸出现后应用；viewport/窗口尺寸改变后重新计算。始终从原始设计值计算，不能对上次已缩放的结果重复乘比例。周期数据刷新应只更新数据；进度填充基于当前布局后的基准宽度，避免旧缓存把适配后的宽度改回去。

## 图片比例与点击区

记录原图与登记后纹理的实际宽高，保留其宽高比；不是所有图片都应设成正方形。对图标默认完整显示，不裁掉图内标题。容器为`boxW×boxH`、源图为`imageW×imageH`时：

```text
k = min(boxW / imageW, boxH / imageH)
drawW = imageW * k
drawH = imageH * k
```

居中放置显示内容，剩余空间留白。若原生按钮底图会直接拉伸到按钮尺寸，可使按钮本身保持源图比例，或用独立图片显示层和较大点击区；后者须检查叠放/可命中设置，并沿用真实按钮UID与回调。不能假定存在未核实的自动contain属性。

正方形原图拉伸到116×104后，整组再等比缩小仍然变形；必须先修正图片显示矩形。父级非等比缩放也会破坏正确的子图片比例。仅比较`GetSize`不够，须比较最终图片内容的显示比例与源图比例。自定义图里的圆形、文字和边框也要用当前截图核对。

## 原生SDK落地时核对

DreamHelper 1.4.7的声明提供`UI:GetUISize`、`SetAnchorType`、`SetPositionByAnchor`、`SetSize`、`SetRenderScale`及屏幕/UI坐标转换。使用时重新核对安装版本、参数和实际语义，不把这些函数名等同于已经完成适配。

`GetPosition/SetPosition`声明以控件左上角为准，顶层UI以屏幕中心为原点；分组子项则相对父组。锚点参数随锚点类型变化，不能把桌面物理像素直接传给它。`SetRenderScale`声明不改变Size属性：已有宽高缩放与render scale只能按明确规则组合，避免重复缩放；字体及图片父级变换也须计入最终结果。

## 验证与随包检查工具

按项目支持范围选择宽高比、最小可用区域、安全边距和DPI。每种情况检查实际存在的HUD及弹窗、长文字、图片比例、边缘控件、关闭入口和点击结果。隐藏控件不算屏幕内显示成功；窗口改变后检查重复刷新不会累积偏移。

可将最终矩形统一为**客户区左上角为原点的物理像素**，交给只读离线工具：

```json
{
  "viewport":{"width":1920,"height":1080},
  "safeInsets":{"left":24,"right":24,"top":24,"bottom":24},
  "widgets":[
    {"id":"button","x":30,"y":30,"width":116,"height":104},
    {"id":"icon","parentId":"button","x":36,"y":30,"width":104,"height":104,
     "image":{"width":1254,"height":1254}}
  ]
}
```

```text
node scripts/ui/run.mjs ui-layout-audit OBSERVED_RECTS_JSON REPORT_JSON
```

工具输入为已采集或候选方案的最终矩形，不会自动查询、修改或导入地图。`visible:false`表示实际不可见，调用者须合并父级显隐；子项矩形也使用客户区坐标，不能传父级相对偏移。传`image`的是图片内容矩形，按钮点击区单独记录。默认边界容差0.5物理像素、图片比例相对误差2%；退出码0通过、2发现问题、1输入/运行错误。检查范围为安全区域、父容器边界、非零尺寸与图片比例，不检查一般遮挡、文字溢出、可读性和点击结果。

离线计算、模拟窗口、实际客户端和真实设备是不同的覆盖范围。几何审计通过后，仍需检查最终渲染、遮挡、文字和同次运行的交互结果。

UI系统尺寸可能随宽高比变化并发生取整。窗口改变后等待重新布局和渲染稳定再采集，不用第一帧判定。字号按SDK支持范围设置，核验长文字换行。

`SetRenderScale`的单位和重置语义须按当前SDK校准，不凭其他引擎惯例写入`1,1`；避免作者尺寸、父级缩放和运行时缩放重复生效。

## 原生操作键周围的按钮组

用户指定围绕跳跃键等原生操作键布置时，保留该相对关系，先实测当前原生键的矩形与锚点，再规划自定义按钮。默认 HUD 布局、玩家按键自定义与 DPI 可能改变位置；只对已测配置承诺，不把某图的右/下偏移写成平台常数。原生按键的隐藏配置见[原生控件显隐](native-controls.md)。

把条件按钮通过正常玩法同时显示出来，检查其完整矩形、相互间距、与原生键的距离和实际命中。例如鱼筐里既有鱼又有杂物并站到收集点，再验证所有相关按钮；空状态下几个按钮未出现不能算整组通过。比例模拟、原生 PC、真实手机分别报告。
