# 运行时模型、特效与短时展示

在已经核实的原生模型/特效与当前 SDK 范围内做展示；这不扩展为任意模型、动作或粒子图的导入制作能力。

## 尺寸、枢轴与朝向

先记录源实例的实际缩放、原生 ActorBounds、模型中心和局部长轴。将包围盒换算回模型尺寸时只除一次已知缩放；SDK `GetSizeBox` 与本次原生包围盒不符时，先定位取值层、缩放和父级差异，不直接用异常读数继续缩放。不要将某个模型的校准值写成所有模型的通用尺寸。

摆到人物身前或上方时，先定义**可见模型中心**的目标，再旋转/缩放局部中心偏移并从目标扣除。改变竖放/横放后要重新计算枢轴补偿；只改角度可能把大模型偏到手边或脚下。分别验证模型长轴、头尾方向、跟随转身、位置中心及不同大小；仅看 Actor 旋转数值不能证明视觉朝向正确。

用户要求居中托举时，先检查是否仍绑定单手插槽。可按 SDK 支持的跟随/挂载方式实现，不默认右手绑定适合所有展示。用户选游戏默认相机时，移除自定义挂载/预设/距离/FOV 等覆盖，按本版能力复位；不以“接近默认”的另一组参数代替该选择。

## 生命周期与状态

显示对象与实际可交互对象共用稳定 ID/状态，避免装饰模型被误认为可收集目标。抓获、换局、返回菜单、结束玩法和迟到 Spawn 回调的清理分别核验；异步复制用本局/本次展示代数防止过期回调重新生成模型。是否同局保留痕迹由玩法决定，不能用“已结束展示”替代新局清理证明。

原生水面、喷泉、沙地等需分别核对渲染、碰撞与粒子组件。Actor 的 `bHidden` 不一定等于粒子系统实际可见；通过本版 SDK、实际组件状态与画面核验。已有喷泉实例的旋转/缩放不等于制作了新粒子图。

## 采样与诊断

短动作或临时举物先在事件发生时立即截图，再做耗时的属性/全场景查询。记录生成时刻与存活窗口，截图前后核对目标仍存在；错过窗口的图片不得用于方向、大小或动作验收。

运行时对象可能在查询期间被正常销毁。优先按已知对象做轻量读取；遇到失效路径，结合目标是否已销毁、当前实例列表及应用日志分类，有限地跳过已确认消失的目标或重新枚举。不要因为检查脚本的竞态就宣称游戏错误，也不能把所有 HTTP/反射失败一律吞掉。编辑器静态地图的整场景快照与运行时短命对象采样分开处理。
